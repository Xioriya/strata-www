Gentoo, refined.

Strata is a GNU/Linux distribution built on Gentoo's package tree, with a faster package manager called Step, a guided installer, and a tuned kernel. You keep the control. You lose the rough edges.

Honest status. Step implements argument parsing, configuration loading, repository sync, package search, and unmasking. The resolver, merge engine, sandbox, and binary package layer are the next milestone. Nothing below is a finished product.

What Strata is

Strata keeps what makes Gentoo good and replaces the rough edges. It does not fork the ebuild tree. It consumes Gentoo's tree unchanged.

Ebuild-native

Gentoo's overlay and repository format, profiles, USE flags, and eclasses work as-is. No conversion layer, no proprietary recipe format.

Step

A C++ package manager with emerge-compatible syntax, a faster resolver and metadata cache, and a one-command unmask flow.

Guided install

Whiptail tools for disks, mounts, base extraction, chroot, and configuration. Every step is a command you can run on its own.

Binhost first

GPKG-compatible binary packages. Pull from Gentoo's binary cache on day one and publish a Strata binhost later.

OpenRC

Predictable service management, no logind dependency, and service scripts that already exist in the Gentoo tree.

Tuned kernel

gentoo-sources plus a performance-oriented Kconfig fragment: 1000 Hz timers, dynamic preemption, ZRAM, and common hardware.

Real documentation

This site is the handbook. Every component has an honest status, a command reference, and a design note.

Open source

GPL-2.0. Step reimplements Portage behaviour, so the license follows. The source, installer, configs, and site are all in one repository.

Install Strata

Not installable yet. The tools exist and the flow is wired, but the base system is still Gentoo's stage3 and Step is not the default package manager. Treat this as an architecture preview. Running setup-disks erases disks.

Planned flow

The installer is a set of small commands. strata-guide is a menu that runs them in order, but each one works alone.

strata-guide
setup-disks
setup-mounts
setup-tar
strata-chroot
strata-setup

Step by step

  1. Partition

    setup-disks lists physical disks, asks for confirmation, and creates a GPT layout: a 1 GiB EFI partition, a 4 GiB swap partition, and the rest as root. Manual partitioning opens cfdisk. Partitions are labelled STRATA-EFI, STRATA-SWAP, and STRATA-ROOT.

  2. Mount

    setup-mounts finds the labelled partitions, mounts root at /mnt/strata, mounts EFI at /mnt/strata/efi, and enables swap. If labels are missing, it asks you to pick partitions.

  3. Extract the base

    setup-tar downloads the latest Gentoo OpenRC stage3, verifies the SHA256 sum, and extracts it into the target. The stage3 URL can be overridden with STRATA_STAGE3_BASE.

  4. Chroot

    strata-chroot bind-mounts /dev, /proc, /sys, and /run, copies DNS configuration, and opens a shell inside the target.

  5. Configure

    strata-setup is a whiptail menu inside the chroot: sync the tree, choose a profile, set the root password, create a user, set hostname, timezone, locale, build a kernel, generate fstab, install GRUB, and enable DHCP.

Bootstrap note

A distribution must be able to build itself. Strata currently bootstraps from Gentoo's stage3 and then uses Portage inside the chroot. Strata stage3 images, built with Step and published to a binhost, are the milestone that makes this a true self-hosted distribution.

Step

Step is Strata's package manager. It is a C++ reimplementation of Portage's orchestration layer with an emerge-compatible command line and a few deliberate usability wins.

Design

Ebuilds are bash scripts. Rewriting them in C++ would not make them faster. Step keeps ebuild phases in bash inside a sandbox and moves the expensive surround work to C++:

LayerOwnerWhy
Argument parsing and UIStep (C++)Instant startup, predictable output
Configuration and profilesStep (C++)Read Portage formats directly
Metadata cacheStep (C++)Parallel generation, stable keys
Dependency resolutionStep (C++)Slots, subslots, blockers, REQUIRED_USE
Fetch and build schedulingStep (C++)Parallelism with clear failure reporting
Ebuild phasesbash + sandboxEbuilds are bash; compatibility wins
Merge and VDBStep (C++)Atomic writes, preserved rebuilds
Binary packagesStep (C++)GPKG read and write

Command line

Emerge syntax is the base. You do not have to relearn flags.

Easier unmasking

Unmasking in Portage means editing package.accept_keywords by hand. Step does it for you and deduplicates the file.

step unmask app-editors/neovim

That appends app-editors/neovim ~amd64 to /etc/portage/package.accept_keywords/strata.conf. Related helpers:

step mask sys-apps/foo
step use app-editors/neovim wayland X

Compatibility

What "faster" means

Step will be measured, not marketed. The benchmarks are dependency resolution on a fixed 50-package set, metadata cache rebuild time, and cold-start time. Compilation time is excluded because no package manager can improve it. Expect clear numbers in the roadmap, not vague claims.

Repositories

Strata uses Gentoo's ebuild tree as its main repository and reads Portage's repos.conf format. Custom overlays work the same way they do on Gentoo.

Default repository

[DEFAULT]
main-repo = gentoo

[gentoo]
location = /var/db/repos/gentoo
sync-type = git
sync-uri = https://github.com/gentoo/gentoo.git
auto-sync = yes

Custom repositories

Drop another file into /etc/portage/repos.conf/:

[my-overlay]
location = /var/db/repos/my-overlay
sync-type = git
sync-uri = https://example.com/my-overlay.git
auto-sync = yes

Sync

step --sync

Step clones the tree if /var/db/repos/gentoo is not a git checkout, and fast-forwards it if it is. step --sync --pretend prints the exact git command without running it.

Inspect

step --info

The info view lists the configuration root, repository root, make.conf path, distdir, VDB root, binhost, every repository location it found, parsed make.conf variables, installed package count, and whether the tree is synced.

Compatibility rules

  • The ebuild tree is never modified.
  • Repository priority and masters follow Portage semantics.
  • Profiles, USE_EXPAND, and masks are read from the repositories and /etc/portage.
  • Custom repositories use the same layout as Gentoo overlays.

Kernel

Strata ships gentoo-sources with a performance-oriented Kconfig fragment and, later, a prebuilt kernel binpkg.

Goals

Responsive

1000 Hz timers, high-resolution timers, dynamic preemption.

Compatible

NVMe, AHCI, USB, EFI stub, ext4, common Ethernet and Wi-Fi.

Lean

No debug info, no KASAN, a -strata localversion.

Memory-aware

ZRAM, ZSWAP, and transparent huge pages enabled.

CONFIG_PREEMPT_DYNAMIC=y
CONFIG_PREEMPT=y
CONFIG_HZ_1000=y
CONFIG_HZ=1000
CONFIG_EXT4_FS=y
CONFIG_VFAT_FS=y
CONFIG_BLK_DEV_NVME=y
CONFIG_SATA_AHCI=y
CONFIG_VIRTIO=m
CONFIG_ZSWAP=y
CONFIG_ZRAM=m
CONFIG_TRANSPARENT_HUGEPAGE=y
CONFIG_DEBUG_INFO_NONE=y
CONFIG_LOCALVERSION="-strata"

Build

emerge sys-kernel/gentoo-sources
cd /usr/src/linux
make defconfig
/path/to/strata/config/kernel/apply.sh /usr/src/linux
make -j"$(nproc)"
make modules_install
make install

Apply script

config/kernel/apply.sh merges strata.fragment into the kernel's .config with the kernel's own merge_config.sh, then runs olddefconfig. The fragment is a baseline, not a universal config. Laptop power management, NVIDIA, and exotic Wi-Fi belong in a local fragment.

LQX

Liquorix patches target Debian kernels and are rebased per release. Strata may offer an optional LQX track later, but the default is a tuned gentoo-sources kernel that the project can maintain reliably.

Roadmap

Each milestone has an acceptance criterion. No dates. A milestone is done when the test passes.

  1. done

    M0 — Reference and harness

    Study Portage's CLI, depgraph, VDB, and GPKG layout. Record emerge's command surface. Clone the reference under Projects/portage-reference.

  2. done

    M1 — Repository skeleton

    Strata repository, installer suite, Portage configs, kernel fragment, documentation site, and Pages deployment.

  3. active

    M2 — Step foundation

    Argument parsing, configuration loading, sync, search, unmask, mask, and use. Shipped in step/. Acceptance: builds clean with -Wall -Wextra -Wpedantic and the config helpers behave correctly.

  4. next

    M3 — Metadata and resolver

    Parallel metadata cache, then a resolver covering slots, subslots, blockers, REQUIRED_USE, and USE flags. Acceptance: dependency graphs match Portage on a fixed test corpus.

  5. next

    M4 — Merge and binpkgs

    Sandboxed ebuild phases, atomic merge, VDB-compatible records, and GPKG read/write. Acceptance: install from Gentoo's binary host, then rebuild the same package from source.

  6. next

    M5 — Benchmarks

    Publish resolution, metadata, and cold-start numbers against Portage on the same hardware and package set.

  7. next

    M6 — Self-hosted Strata

    Strata stage3 images built with Step, a Strata binhost, and Step as the default package manager. Acceptance: build a stage3 from Strata, boot it, and rebuild it.

FAQ

Is Strata just Gentoo with a script?

Today, close. The installer bootstraps from Gentoo's stage3 and uses Portage inside the chroot. Strata becomes its own distribution at M6, when Step builds Strata stage3 images and Strata is self-hosted.

Is Step a fork of Portage?

No. Step is a clean-room C++ implementation. Portage is used as a behavioural reference and test oracle. Step does not copy Portage source. Both are GPL-2.0.

Why C++?

Fast startup, predictable memory use, and direct control over scheduling and caching. The speed win is in resolution, metadata, and merge work, not in compiling packages.

Will binary packages work?

Yes, through GPKG compatibility. The plan is to install from Gentoo's binary host immediately and publish a Strata binhost later.

Why OpenRC instead of dinit?

Gentoo's packages ship OpenRC service scripts. Compatibility reduces maintenance and avoids maintaining a parallel service tree. dinit can be an opt-in track later.

Why not use Gentoo's repo with a totally new recipe format?

Because ebuild compatibility is the point. A new format would require an importer and would lag behind the tree. Strata consumes ebuilds directly.

When can I install it?

Not yet. The installer flow is wired but the base is Gentoo's stage3 and Step is not the default package manager. Watch the roadmap for M6.

What hardware is targeted?

x86-64 with UEFI. The kernel fragment covers common desktop, laptop, and virtio hardware. Non-x86 ports are out of scope for now.

How can I help?

Benchmark Portage, test the installer in a virtual machine, improve the documentation, or work on resolver parity tests. See the Contribute tab.

Design rules

  • Never modify the Gentoo ebuild tree.
  • Never claim a feature works before it has a test.
  • Keep the installer steps independent and idempotent where possible.
  • Report errors with the failing command, not a generic message.
